# Independent bone shear evaluation

Bone axes and hierarchy semantics follow the public [Bones](https://esotericsoftware.com/spine-bones), [Tools](https://esotericsoftware.com/spine-tools), [runtime skeletons](https://esotericsoftware.com/spine-runtime-skeletons) and [4.3 API](https://esotericsoftware.com/spine-api-reference) descriptions. This implementation was written from general affine mathematics and observations of original bone-only JSON fixtures; no editor/runtime implementation, function body, source map or runtime constant was inspected.

For the normal-inheritance subset, the independently proposed X direction is `rotation + shear_x`; Y is `(rotation + 90) + shear_y`. Signed scale multiplies each basis column and world matrices compose parent-first. Stored angles and animation values remain unmodified.

On November 6, 2026 four original unit-root inputs at exactly 1, 10, 45 and 90 degrees were executed through a separately licensed Spine 4.3.13 runtime's public SkeletonJson/Skeleton/AnimationState/appliedPose API. Dividing `atan2(c,a)` by each authored angle yielded degree-to-radian candidates. Searching at most eight adjacent f64 values either side of those measurements selected the unique exact-best coefficient `0.01745329277777778`, IEEE bits `3f91df46a6c0950b`, with zero observed residual at all four angles. This selection preceded held-out evaluation. Six nearby coefficients fit within 1e-15 but diverged strongly at large angles; the committed calibration and held-out tests pin the actual observations.

Raw f64 angle sums with that observed coefficient predicted 157 finite held-out sample matrices exactly in the independent JavaScript probe, including signed/complete turns, reflected nonuniform parents, small/zero/parallel scales and exactly f32-representable huge angles. A separate f32 storage/composition emulation stayed within 0.000002944. Existing Bezier interpolation remains the independently observed ten-segment policy. The compiled Rust evaluator is tested against recorded numeric columns rather than against another copy of its formula.

An additional original opposite-huge input `r=f32(1e20), shear_x=shear_y=-r` produced columns `(1,1,0,0)`, establishing left-to-right association for the Y angle sum: regrouping to `(r+shear_y)+90` produces a different result. Do not pre-reduce angles or replace this with a generic tangent-skew matrix.

Complete local scripts, all failed Pi/modulo/overflow variants, unchanged input SHA256 manifests, actual matrices and calibration candidate sets remain in the coordinator's local evidence `shear-runtime-probe-20261106T065302Z-369614` and `shear-core-20261106T073006Z-160bcd`. Inputs were original bone-only fixtures; no private artwork or official implementation is committed or redistributed. These are bounded numeric data observations, not proof of every platform's trig backend, UI convention, mixing policy or full Spine compatibility.
